# ego-lite (ego-browser) - 使用指南

> 生成时间: 2026-10-25

## 1. 快速开始

### 1.1 环境要求

| 要求 | 版本/说明 |
|------|-----------|
| ego lite 桌面应用 | macOS（Apple Silicon / Intel）或 Windows x64；Linux 在路线图中（未支持）。浏览器是闭源免费应用，**必需**——`ego-browser` 命令与浏览器运行时都由它提供 |
| Node.js | ≥ 22（仅开发本仓库需要；终端用户无需自装 Node） |
| Agent CLI | 任意（Claude Code、Codex、Cursor、自定义…），通过 Skill 或插件接入 |

### 1.2 安装

**方式 A：下载应用**（推荐终端用户）

- macOS: https://cdn.ego.app/setup/macos/arm64/egolite-Y7MbxKIuhzFB.dmg （Intel 版同页）
- Windows: https://cdn.ego.app/setup/windows/x64/egoliteSetup-Y7MbxKIuhzFB.exe
- 安装并打开应用，完成首次引导（可选迁移 Chrome 登录态/Cookie/扩展/书签），引导会把 `ego-browser` 命令注册到 PATH（macOS/Linux 通常在 `~/.local/bin`；**Windows 需新开终端才能看到 PATH 变化**）。

**方式 B：只装 Skill**

```bash
npx skills add citrolabs/ego-lite
```

首次执行浏览器任务时，Skill 会引导安装 ego lite 应用。

**方式 C：让 Agent 自己装**（macOS 有自动脚本）

```text
Set up ego lite for me: https://github.com/citrolabs/ego-lite
Read `skills/ego-browser/references/install.md` and follow the steps to install ego lite.
```

macOS 可自动执行 `sh skills/ego-browser/scripts/install.sh`（下载 DMG → 安装到 /Applications → 去 quarantine → 启动）；**Windows 无脚本**，从官网下载 exe 手动安装（SmartScreen 拦截时选"更多信息 → 仍要运行"）。

### 1.3 快速运行

安装完成后的验证（macOS/Linux）：

```bash
command -v ego-browser          # 确认命令存在；不在则 export PATH="$HOME/.local/bin:$PATH"
ego-browser skill               # 打印与安装版本匹配的完整使用指南（含结束标记）
ego-browser nodejs <<'EOF'
console.log('ego-browser ready')
EOF
```

第一个任务：在 Agent CLI 中输入

```text
/ego-browser follow @ego_agent on x.com for me
```

或手写第一段脚本：

```bash
ego-browser nodejs <<'EOF'
const task = await taskSpace("demo");
const page = task.page("p1");
await page.goto("https://example.com");
console.log({ spaceId: task.spaceId, snapshot: await page.snapshot() });
EOF
```

本仓库开发者的运行方式（无子命令、脚本走 stdin）：

```bash
cd package/ego-browser
npm install && npm run build
node dist/out/index.js <<'JS'
console.log('hello from repo CLI');
JS
node dist/out/index.js -h        # 帮助
```

注意：仓库 CLI 真正驱动浏览器同样需要 ego 运行时（`globalThis.ego` 绑定）；没有 ego lite 应用时只能执行纯 Node 部分。

## 2. 配置说明

### 2.1 配置文件

无必填配置文件。可选 `.env` 文件按顺序加载（`src/env.ts:39-42`）：

| 文件 | 说明 |
|------|------|
| `<repo 根>/.env` | 开发本仓库时的环境 |
| `<agent workspace>/.env` | Skill 工作区级环境（agentWorkspace() 目录下） |

### 2.2 环境变量

| 变量 | 必需 | 说明 |
|------|------|------|
| `EGO_BROWSER_AGENT_WORKSPACE` | 否 | 覆盖 agent 工作区目录（默认：捆绑的 Skill → 仓库 `skills/ego-browser`）。支持 `~/` 前缀（自动展开 HOME/USERPROFILE） |
| `EGO_BROWSER_NAME` | 否 | 实例名，默认 `default` |
| `EGO_BROWSER_REAL_E2E_CLI` | 否 | E2E 指定 ego-browser CLI 路径（默认 macOS 查找 `/Applications/ego lite.app/.../ego-browser`，否则用 PATH 上的 `ego-browser`） |
| `CI=true` | 否 | `npm install` 时跳过 lefthook 安装（prepare 钩子） |

### 2.3 工作区解析优先级

`EGO_BROWSER_AGENT_WORKSPACE` → `dist/out/agent-skills/ego-browser`（构建捆绑）→ 仓库 `skills/ego-browser`（开发回退）。

## 3. 主要功能

### 3.1 运行浏览器脚本（核心功能）

**说明**: 把多步任务写成一段 JS 一次执行，而不是"调两个命令看一次结果"的循环——这是 ego 相对 CLI 式工具的核心卖点（更快、更省 token）。

脚本在 **Node.js**（非网页）中运行：浏览器助手与 Node API 直接用；页面内代码放进 `page.evaluate()`；不要 import Playwright 或另起浏览器。脚本不继承 shell 的 cwd 与环境变量，读写本地文件一律用绝对路径。

**各 shell 的调用形式**（skill-body/SKILL.md 详细约定）：

```bash
# Bash / Zsh / Git Bash：heredoc
ego-browser nodejs <<'EOF'
const task = await taskSpace("inspect example page");
await task.page("p1").goto("https://example.com");
console.log(await task.page("p1").snapshot());
EOF

# 沙箱禁 heredoc 时：-e（单引号包代码，代码内字符串用双引号）
ego-browser nodejs -e 'console.log(await (await taskSpace("t")).page("p1").title())'
```

```powershell
# PowerShell 5.1 无 heredoc，且给原生程序传参会丢内部双引号：
# 把完整任务写进 UTF-8 编码的 .mjs 文件，再用 ASCII 单行入口执行
ego-browser nodejs -e "await import('file:///C:/Users/<name>/ego/task.mjs')"
# 切忌 Get-Content 管道（5.1 按 ANSI 读、只发 ASCII，非 ASCII 会损坏）
```

```bat
:: cmd 支持 stdin 重定向，直接喂 .mjs 文件
ego-browser nodejs < C:\Users\<name>\ego\task.mjs
```

多轮协作约定：每轮新进程；为每个目标建独立目录（如 `C:/Users/<name>/ego/laptop-prices-20260922-1405/`），每轮写**新的完整文件**（`round-01.mjs`、`round-02.mjs`…），不要编辑旧文件重放。

### 3.2 Spaces（任务空间）与 Pages

**说明**: 每个任务一个隔离 Space，与用户自己的浏览互不抢占。

```js
const task = await taskSpace("price research"); // 名字唯一：重名即恢复自己的空间
console.log(task.spaceId);                      // 打印给后续轮次
const page = task.page("p1");                   // 新空间自带 p1；page() 只取不建
await page.goto("https://example.com");
const p2 = await task.newPage();                // 确需多页时再开
// 后续轮次恢复：
const resumed = await taskSpace(7);             // 用 spaceId
```

要点：一个用户目标只用一个 Space；不要用新 Space 掩盖卡死的 Page；`task.page("p2")` 句柄永远真值，判断标签是否存在要用 `await task.pages()` / `await task.tabs()`。

### 3.3 快照与引用操作

```js
const snap = await page.snapshot();   // 结构化文本 + @N 引用（市场最强快照，深嵌 iframe 可靠）
await page.click("@12");              // 操作引用
await page.click('loc=role:button[name="Search"]');  // 稳定定位器（推荐复用）
await page.waitForSelector('loc=href:/releases');
```

`@N` 引用短寿命：导航或 DOM 变化后需重新快照；跨轮复用优先 `loc=css:` / `loc=role:` / `loc=href:`。

### 3.4 输入、等待、弹窗、下载、截图

```js
await page.fill("@5", "hello");
await page.keyboard.press("Control+A");       // 平台无关写法，无需关心 OS
await page.keyboard.paste({ text: "…", html: "<b>…</b>" });  // 剪贴板事务，用完自动恢复
await page.waitForLoadState("domcontentloaded");
await page.acceptDialog();                     // JS 对话框（弹窗会阻塞其他命令）
const file = await page.waitForDownload();     // 下载工件
const png = await page.screenshot();
```

### 3.5 控制权交接（人类协作）

```js
await task.handOff();               // 交还给用户（如需要用户手动过验证码/登录）
// 用户操作后，agent 侧：
const task2 = await takeOverTaskSpace(spaceId);   // 经用户批准接管
const userTab = task2.userPage();                  // 接管边界上的活跃标签页
```

### 3.6 站点学习（经验积累）

```js
const ctx = await learnContext("github");                    // 读取该站点的经验笔记
const r = await runSiteTool("github", "search-repos", { q: "ego" });
const stats = await runSiteBrowserTool("github", "repo-stats", { repo: "citrolabs/ego-lite" });
```

内置站点包：github、google、x-com（位于 `skills/ego-browser/learnings/`）。

## 4. API 接口

### 4.1 v2 公共面（`public-api-schema.ts` 摘录）

| 接口 | 签名 | 说明 |
|------|------|------|
| profiles | `await profiles()` | 列出可用于新空间的浏览器配置 |
| listTaskSpaces | `await listTaskSpaces()` | 列出 agent/用户拥有的空间 |
| taskSpace | `await taskSpace(nameOrId, { profileId? })` | 复用或创建 agent 空间；用户占用名 → `EGO_TASK_SPACE_NAME_IN_USE` |
| claimTaskSpace | `await claimTaskSpace(spaceId)` | 经批准认领用户空间 |
| takeOverTaskSpace | `await takeOverTaskSpace(spaceId)` | 经批准恢复 agent 空间 |
| TaskSpace.page | `task.page(label)` | 已存在 Page 的惰性句柄（不创建、不校验） |
| TaskSpace.pages / tabs | `await task.pages()` / `await task.tabs()` | 受管 Pages / 全部标签（含未纳管） |
| TaskSpace.newPage / adopt / release | — | 建页 / 纳管未管理标签 / 停止管理 |
| TaskSpace.waitForControl | `await task.waitForControl({interval?, timeout?})` | 等待控制权而不抢占 |
| TaskSpace.handOff / finish | — | 交还用户 / 结束（keep 选项） |
| Page.* | goto / click / fill / press / snapshot / evaluate / cdp / waitFor* … | 驱动页面 |
| 鼠标键盘 | `page.mouse.*`、`page.keyboard.*` | 低层输入 |

完整清单在运行时打印：`help()`（全部）、`help("page.click")`（单个 API 的签名与不常用选项）、`help("profiles")`。**不要**按 Playwright 的方法名类推（没有 `locator()`/`getByRole()`/`expect()`）；不够用时走 `page.evaluate()` / `page.cdp()` 逃生舱。

仅这些指针方法接受可选 `label`：`click()`、`dblclick()`、`hover()`、`dragAndDrop()`、`mouse.click()`、`mouse.move()`、`mouse.wheel()`（3-6 词的动作描述，跟随可见的 agent 光标）。

时间参数一律**毫秒**（v1 兼容助手保持原单位）。v1 全局助手仅为旧脚本兼容保留，新脚本一律用 TaskSpace/Page。

## 5. 开发者指南（本仓库）

```bash
git clone https://github.com/citrolabs/ego-lite && cd ego-lite/package/ego-browser
npm install          # Windows 注意：prepare 钩子会失败，见《Windows兼容性分析》8.1
npm run build        # esbuild → dist/src；rollup → dist/out/index.js；渲染+复制 Skill
npm test             # build + skill 翻译检查 + typecheck + node --test（36 个测试文件）
npm run e2e          # 真实浏览器 E2E（37 用例，自包含 fixture，勿手动接管运行中的空间）
npm run validate:site-skills   # 校验 learnings
npm run style:check  # prettier
```

构建产物：`dist/src/**`（测试目标）、`dist/out/index.js`（单文件 CLI，bin 入口）、`dist/out/ego-browser/SKILL.md`（带版本与结束标记的指南）、`dist/out/agent-skills/ego-browser`（入口 Skill + learnings 拷贝）。

贡献约束摘录（AGENTS.md/CONTRIBUTING.md）：新 v2 API 需同步 `public-api-schema.ts` → 运行时校验 → `help()` → 架构文档 → `skill-body/SKILL.md`；元素解析失败用带 `transient`/`permanent` 的 `ElementResolutionError`；站点技能必须"站点形状"可验证。

## 6. 常见问题

### Q: `ego-browser` 命令找不到？
A: 先确认 ego lite 已安装并完成首次引导。macOS/Linux：`export PATH="$HOME/.local/bin:$PATH"`；Windows：**新开一个终端**（旧终端保留启动时的 PATH）。仍不行则重开 ego lite 应用、完成引导后重试。

### Q: `ego-browser skill` 报 `Unknown command: skill`？
A: 安装的 ego lite 版本老于 Skill。经用户同意后运行 `ego-browser upgrade`；`upgrade` 也不存在则按第 1.2 节重装。

### Q: 报 `SyntaxError: await is only valid in async functions...`？
A: 几乎总是 shell 把脚本破坏了（PowerShell 5.1 丢引号/编码），不是代码问题。**不要**包 IIFE、不要开新空间、不要重发同一命令；改用 `.mjs` 文件 + `file:///` 导入（PowerShell）或 `<` 重定向（cmd）。

### Q: 输出的指南好像被截断了？
A: `ego-browser skill` 的输出以 `[ego-browser:skill] end of guide` 结尾；缺失即截断。重定向到文件再分段读：`ego-browser skill > "$TMPDIR/ego-browser-skill.md"`（PowerShell: `> "$env:TEMP\ego-browser-skill.md"`）。

### Q: Windows 上 `npm install` 在 prepare 步骤报错？
A: prepare 钩子用了 POSIX shell 语法。临时解法：`npm config set script-shell "C:\Program Files\Git\bin\bash.exe"` 后重装；根治见《Windows兼容性分析》8.1。

### Q: 能在 Linux 上用吗？
A: 暂不能（浏览器无 Linux 版，见 roadmap）。但本仓库的单元测试可在任意平台跑（`npm test`），E2E 需要 macOS/Windows 上的真实 ego 应用。
