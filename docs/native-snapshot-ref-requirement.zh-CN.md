# 原生快照需求（规格）

> 中文翻译版 · 英文原文：[native-snapshot-ref-requirement.md](native-snapshot-ref-requirement.md)

## 紧凑快照文本

在序列化 `content` 之前，请先对快照树做简化：

- 省略空的、纯空白的（含 NBSP）、或只含零宽格式字符的文本节点。
- 省略已无剩余子节点的无名 `container`。
- 用其仅剩的子节点替换无名 `container`。
- 保留拥有多个子节点的无名 `container`，因为它们保留了分组信息。
- 保留有名或带 ref 的容器，以及语义节点，例如 `image`、`svg_root`、`canvas`、`iframe`、`root`、列表项和表格单元格。

该变换必须保持剩余节点的顺序、refs、稳定定位器、URL 以及 iframe 边界。它对视口快照和全页快照同样适用。绝不因为页面文本"不可交互"、因为其父容器被简化、或在清理定位器元数据的过程中，移除或改写非空的页面文本。

验收标准：一个包含嵌套容器、空白文本、两个兄弟分组、一个 iframe、一张图片、一个 SVG、一个 canvas 和一个空表格单元格的测试夹具被捕获两次。第二次捕获的紧凑输出与第一次完全一致，兄弟分组保持可区分，且每个 ref 仍解析到其原始节点。

## 延后项：定向快照范围

未来的快照 API 应能将捕获范围限定为由当前 ref 或选择器选定的某个子树，包括 iframe 或 OOPIF 内部的内容。浏览器应在序列化快照**之前**应用该范围；在 JS 中对全量快照做过滤并不能减少原生侧的工作量与传输内容。

被选定的根必须唯一解析、保留 Page 与帧的归属信息，并产生对正常 Page 动作仍然有效的 refs。根缺失或存在歧义时应清晰报错。确切的公开 API 刻意悬而未决，且本需求未排入当前实现计划。

## iframe 内容的快照引用

`ego.snapshot()` 已经包含来自普通 iframe 与 OOPIF 的文本，但这些帧内部的可操作节点目前被排除在 `refs` 之外。其结果是：内容看得见，却没有对应的 `@N` 目标。

请为快照打印的每个可操作帧节点返回一个 ref：

```js
{
  refId: 901,
  backendNodeId: 21,
  frameId: "FRAME_OR_OOPIF_TARGET_ID",
  role: "button",
  name: "Run iframe action",
}
```

- `content` 必须为该节点打印 `[ref=901]`。
- `refId` 在一次快照内必须唯一，包括跨渲染进程的情形。它是展示给 Agent 的编号。
- `backendNodeId` 仍然是节点在其所属渲染器内的本地节点 id。
- `frameId` 标识拥有该节点的帧。对顶层文档可以省略。
- 捕获快照不得激活、聚焦或重载任何帧。

验收标准：一个页面包含一个同源 iframe 和一个跨源 OOPIF，不同渲染器中出现重复的 backend node id。每个被打印的 button 和 textbox 都拥有各自不同的 ref，且每个 ref 都解析到其所在帧中的那个节点。

当某个 backend node id 只有一个可能的宿主时，ego-browser 现已能从帧的 AX 树回填缺失的 `frameId`。当渲染器本地的 backend id 出现重复，以及可操作帧节点被整个排除在 `refs` 之外时，仍然需要原生元数据。

## 稳定定位器的正确性

稳定定位器必须唯一地解析到产生该快照 ref 的同一节点。以下情形均属无效：匹配不到任何节点、匹配到多个节点、或唯一匹配到了一个**不同的** `backendNodeId`。

请在原生测试中至少覆盖以下用例：

- 同一文档内的重复控件，例如同名的多个按钮；
- 一个隐藏副本与一个可见编辑器共享同一个可访问名；
- 同一 role 与 name 分别出现在顶层文档和某个 iframe 中；
- 定位器的元素类型与源节点不符。

当唯一性与节点同一性无法同时成立时，省略该定位器。不要在 `content` 中序列化 `loc=unstable` 或 `loc=ambiguous`，也不要在 `refs` 中使用这些状态字符串。JS 运行时会校验已声明的定位器并省略无效项，作为兼容性兜底。
